Multi-Account Quote Platform

Design proposal for evolving quotes-social-media from a single-user generator into an autopilot system managing 20+ Instagram accounts with self-sustaining quote pools, scheduled publishing, and full isolation.

Phase 2 2026-07-08 v0.2 Proposal

Current vs. Target

🟡 Current State

  • 📄 Single flat quotes/sample.txt — manual edits
  • 👤 One user, one Instagram account
  • ⏰ Manual trigger — CLI or web button
  • 📋 Single publish queue, one daily slot
  • 🔁 No quote recycling or cooldown
  • 🏷️ No categories or themes

🟢 Target State

  • 🧠 Self-managing quote pool — AI inflow, cooldown, retirement
  • 👥 20+ isolated accounts, each with theme + schedule
  • 🤖 Fully automated — daily cron triggers everything
  • 📅 Per-account publish queues with timezone-aware schedules
  • ♻️ Quote lifecycle: available → used → cooldown → recycle
  • 🏷️ Categories + engagement tracking per quote

Each account is a fully isolated sandbox with its own theme, schedule, queue, and Instagram connection. The quote pool is shared across accounts but each quote tracks which account used it.

Quote Pool Lifecycle

stateDiagram-v2 [*] --> Available: Imported / AI-generated Available --> Used: Picked for batch Used --> Cooldown: Posted to Instagram Cooldown --> Available: 30 days elapsed Available --> Retired: Never used for 90 days Retired --> Available: Manual restore Cooldown --> Retired: Used 5+ times
State Definition Auto-transition
Available Ready to be picked for any account → Used when selected for a batch
Used Picked but not yet posted (in publish queue) → Cooldown after successful post
Cooldown Recently posted — hidden from selection → Available after N days (configurable per account)
Retired Stale or overused — excluded from autopick → Available only via manual restore

Account Sandbox Model

Each account is a first-class isolated unit. Everything lives under output/accounts/<account-id>/.

Proposed CLI Commands

# Account management
npm run cli account create dailygrind --theme motivation,life --time 09:00 --tz America/New_York
npm run cli account list
npm run cli account config dailygrind --set cooldownDays 14
 
# Quote pool
npm run cli quotes list --status available --theme motivation
npm run cli quotes generate --count 20 --theme philosophy
npm run cli quotes add "The unexamined life is not worth living." --theme philosophy --author Socrates
npm run cli quotes stats
 
# Generation (account-scoped)
npm run cli generate --account dailygrind --count 2
npm run cli generate --account deepthoughts --dry-run
 
# Publishing
npm run cli publish --account dailygrind
npm run cli publish --all                    # all enabled accounts
npm run cli publish --status
 
# Autopilot daemon
npm run cli daemon start                    # starts the scheduler
npm run cli daemon status
npm run cli daemon stop

Risks & Open Questions

🔴

IG Rate Limits + Anti-Spam

20 accounts posting daily = ~20 API calls/day minimum. Meta's rate limits and anti-spam detection are aggressive for new accounts. Accounts need to be aged and warmed up before heavy use. We need a rate limiter and gradual ramp-up.

🔴

Instagram Auth Rotation

Dev tokens expire in ~2 hours. Long-lived tokens last 60 days. Need a token refresh system for 20+ accounts or we'll wake up to 20 failed posts.

🟡

AI Quote Quality

AI-generated quotes can be generic. Need a quality gate: minimum length, uniqueness check against pool, sentiment/toxicity filter.

🟡

Daemon Reliability

The autopilot scheduler needs to run 24/7. Currently the app is a Next.js server + CLI. Options: (a) cron job, (b) persistent daemon process, (c) GitHub Actions scheduler. Each has tradeoffs for 20 accounts.

❓

Open Question: Template Management

Should each account have its own template set, or should templates be global with accounts selecting a subset? Different accounts may want distinct visual identities.

❓

Open Question: Content Originality

With 20 accounts all pulling from the same quote pool, how do we ensure two accounts don't post the same quote on the same day? Need cross-account dedup in the picker.
